# Private Web Edition deployment

Use this branch for an access-restricted preview. The operator receives the username, chosen sites and client connection details. Selected websites see requests from the hosting provider. Ask testers to use accounts they control or have permission to check. Hosting proxies may retain connection metadata under their own retention policy.

## Hosting decision

**Render Free Web Service** is the first candidate for a single same-origin Docker service. Use one instance and one Uvicorn worker so resource limits apply to the whole service. Render's documented free-service model includes idle sleep and a monthly workspace-wide pool of free instance hours. Budget provisionally for 512 MiB RAM, 0.1 CPU, 750 instance-hours/month and a cold start after 15 minutes idle. The operator must check the current limits and free custom-domain allowance in the chosen workspace before creating a service. This environment could not retrieve Render's live pricing or acceptable-use pages. A free plan and outbound HTTPS availability do not establish provider permission for a username discovery service. Review the use policy, including abuse, unsolicited traffic and high outbound traffic restrictions. If the intended workload needs provider approval, obtain it before inviting testers. [Free services](https://render.com/docs/free) · [Web services](https://render.com/docs/web-services) · [Outbound networking](https://render.com/docs/outbound-ip-addresses) · [Acceptable use](https://render.com/aup)

**Hugging Face Docker Spaces** supports HTTP/HTTPS egress, with CPU Basic listed at 2 vCPUs, 16 GB RAM and 50 GB ephemeral disk. Its current documentation requires a paid plan to create Docker Spaces and restricts custom domains to PRO or organizational plans and public/protected visibility. That rules it out for a new zero-cost custom-domain deployment. Docker can serve streaming HTTP; proxy buffering still requires an end-to-end test. Its content policy also applies to hosted applications. [Hardware and egress](https://github.com/huggingface/hub-docs/blob/58f8f5b9376a25dee4c9afc3192fe86d7159c41a/docs/hub/spaces-overview.md) · [Custom domains](https://github.com/huggingface/hub-docs/blob/58f8f5b9376a25dee4c9afc3192fe86d7159c41a/docs/hub/spaces-custom-domain.md) · [Content policy](https://huggingface.co/content-policy)

## Owner deployment steps

1. Sign in to an authorized Render workspace, confirm the free plan and use policy, and grant repository read access. Use **New → Blueprint**, select this repository, choose branch `feat/web-edition` and its root `render.yaml`. Review the plan before applying. Leave automatic deployment off.
2. Generate a random password of at least 32 characters using a password manager and supply it through Render's secret settings as `HUNTWICK_WEB_PASSWORD`. Share it only with approved testers. Use HTTPS, including for the first browser login. Do not put credentials in a URL, Git commit or screenshot.
3. Deploy manually. At the provider-assigned HTTPS address, confirm `/healthz` responds, and a fresh browser requires authentication to open both the app and `/api/catalog`. Sign in with username `huntwick`. Verify the scoped directory, stream completion and a browser export. For an offline application-level check, select **GitHub only** and enter `with_underscore`; Sherlock rejects that handle for GitHub without contacting the site.
4. Validate real streaming through the provider proxy with one approved limited check. Check memory at maximum admitted concurrency, cold-start latency, egress availability and absence of sensitive logs. If admission limits exceed free memory, reduce the admitted load before inviting testers. Keep the preview password enabled.

## Future custom domain

After separate approval, add `huntwick.isharalakshan.xyz` in the service's **Settings → Custom Domains**. At the authoritative DNS provider, add the CNAME for host `huntwick` pointing to the exact Render hostname shown in the dashboard, without a URL scheme or path. Resolve any conflicting records for that host, verify the domain in Render, wait for the managed TLS certificate, set HUNTWICK_PUBLIC_ORIGIN to the exact HTTPS custom origin in the service environment, restart the service, and repeat the unauthenticated/authorized checks over HTTPS. This switches the origin accepted for browser search requests from the provider URL to the custom domain. Add the Tools listing at `isharalakshan.xyz/tools/huntwick/` only after publication approval. [Render custom domains](https://render.com/docs/custom-domains)
