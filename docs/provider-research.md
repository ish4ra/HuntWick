## Enhanced Search

The bundled [native catalog](../engine/data/native-v1.json) records schema version, revision, validation level, original HuntWick MIT rules and official source for each route. A catalog hash and schema checks protect the packaged data. The adapter runs one provider per selected platform. Equivalent pinned Sherlock aliases share a check when their rules agree. Different request methods for the same profile retain both rule verdicts in the result details. Historical data stays readable.

- Bluesky uses the public AppView getProfile lexicon. A plain name maps to the default bsky.social handle. A supplied domain handle stays intact. A positive requires the matching handle and DID. [Official schema](https://github.com/bluesky-social/bsky/blob/d92c6fe74100d33b5250f076b767e6bb8cea9026/lexicons/app/bsky/actor/getProfile.json)
- Lichess uses its public user endpoint and asks the service to omit profile details, rankings and trophies. A positive requires matching ID and username. A denial or rate limit remains visible. [Official endpoint](https://github.com/lichess-org/api/blob/fd0c43efd7ca228e489a7259290cd7dabbc7c5bf/doc/specs/tags/users/api-user-username.yaml)
- osu! accepts a same-origin redirect to a numeric user page as a Possible Match. An API v2 user lookup needs OAuth credentials. HLTV community profiles have numeric IDs. A supported automated username lookup could not be established, and the cloud returned 403 for the terms page. No HLTV rule ships. [osu! documentation](https://osu.ppy.sh/docs/) · [HLTV terms](https://www.hltv.org/terms)
- crates.io and Chess.com use public profile lookup routes. GitHub and GitLab use their public user APIs. A returned handle and stable ID must agree. Ambiguous data stays inconclusive. Responses are processed in memory. Tests cover synthetic positives, negatives and denials. The cloud could not fetch the Chess.com support article, so live checks from the owner's network remain important. [crates.io implementation](https://github.com/rust-lang/crates.io/blob/d217167affabb2bcc090acb48ea14d84ae03e9b9/src/controllers/user/other.rs) · [Chess.com published API](https://www.chess.com/news/view/published-data-api)
- Rule updates ship in signed application versions. Installing a previously retained, checksum-verified package restores its bundled snapshot. Independent signed catalog distribution and atomic rollback await a separate trust and compatibility design. Hosted search accepts only its existing GitHub and GitLab routes.

## After RC.4 owner testing

Prioritize additional providers and platform definitions with maintained public lookup rules, clear redistribution terms and positive, negative and denial fixtures. Evaluate licensed catalog imports separately from signed catalog delivery and rollback. [RC.4 owner checks](rc4-acceptance.md)
